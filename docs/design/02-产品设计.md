## 1. 设计原则

从需求文档的核心洞察推导出四条产品设计铁律，所有页面与交互决策以此为准绳：

| # | 原则 | 含义 | 反例（禁止出现） |
|---|------|------|------------------|
| D1 | **30 分钟原则** | 业务员每日在本产品内的必要操作 ≤30 分钟；默认视图永远是"今天该我做的事" | 打开产品先看到空荡荡的列表页，需要自己找活干 |
| D2 | **AI 干活，人拍板** | AI 的每个产出（线索、信、回复）都以"待确认的成果"形式呈现，一键通过/修改/拒绝 | 让用户从零开始写信、从零筛选线索 |
| D3 | **可解释，不黑箱** | 每条 AI 决策附一句话依据（为何选这家、为何这样写、为何判为热线索） | 只给分数不给理由 |
| D4 | **信誉安全兜底** | 一切可能损害发信信誉的操作（提量、加账号、改频率）都有护栏与刹车，宁可保守 | 允许用户一天群发 500 封 |

**产品人格**：一个勤恳、专业、汇报清晰的"开发助理"。文案语气用第一人称汇报式
（"我昨晚为你找到 120 家公司，其中 34 家高度匹配"），而非工具式（"查询结果：120 条"）。

## 2. 用户角色与权限

| 角色 | 说明 | 权限要点 |
|------|------|----------|
| 业务员 (Member) | 主用户 | 管理自己的 Campaign、线索、收件箱；只见自己的数据 |
| 主管/管理员 (Admin) | 老板或销售主管 | 全团队数据看板；管理成员、品牌资产库、发信域名、套餐账单；审批权限阈值设置 |
| SOHO（单人租户） | 一人公司 | = Member + Admin 合一，界面自动隐去团队功能 |

团队级规则：**线索全租户去重**——同一公司域名同时只能被一个成员的 Campaign 触达
（防同事撞客户，需求 FR-SYS-01）；成员离职由 Admin 转移其 Campaign 与线索。

## 3. 信息架构与导航

```
顶栏：Logo | 全局搜索（公司/联系人/邮件）| 配额余量 | 通知铃 | 头像
侧栏（6 个一级入口，MVP 全部交付）：
├── ① 今日待办  Today          ← 默认落地页（D1 原则）
├── ② 收件箱    Inbox           热线索队列 + 全部回复
├── ③ 开发任务  Campaigns       任务列表 → 任务详情（含四步创建向导）
├── ④ 线索库    Leads           全租户线索池（公司/联系人两个视角）
├── ⑤ 数据报表  Analytics       漏斗 / 送达健康 / （Admin）团队看板
└── ⑥ 设置      Settings        邮箱与域名 / 品牌资产库 / 团队 / 合规 / 套餐用量
```

层级约束：任何核心对象（线索、邮件、回复）距离首页 ≤2 次点击。
移动端（第 2 期）只做 ①② 两个入口：热线索通知、快速审批与回复。

## 4. 核心对象模型（产品语义层）

产品中用户可感知的六个核心对象及其关系——这也是后续架构设计的领域模型输入：

```
租户 Tenant
 ├─ 成员 Member
 ├─ 品牌资产库 BrandKit（公司介绍/产品卖点/认证/案例/FAQ —— AI 写作唯一事实源）
 ├─ 发信身份 SendingIdentity（发信域名 + 邮箱账号 + 信誉状态 + 预热进度）
 ├─ 压制名单 SuppressionList（租户级全局：退订/投诉/硬退信/手工拉黑）
 └─ 开发任务 Campaign（属于某成员）
     ├─ ICP 定义（目标市场/行业/公司类型/规模 + 自然语言补充）
     ├─ 话术策略 Playbook（价值主张、序列步骤定义、A/B 变体）
     └─ 线索 Lead（公司）
         ├─ 联系人 Contact（含邮箱置信度）
         ├─ 研判档案 Research（AI 收集的公司事实 + 出处链接）
         ├─ 序列状态 SequenceState（见 §6 状态机）
         └─ 会话 Thread（往来邮件 + AI 分类 + 交接记录）
```

**关键语义规则**：
- Lead 的唯一性按 **公司域名** 在租户内全局判定（去重与撞单保护的基础）；
- 压制名单优先级高于一切：命中即从任何序列中永久移除；
- Research 中每条事实必须带出处 URL（D3 + 反幻觉：写信只能引用 Research 与 BrandKit）。

## 5. 核心用户旅程

### 5.1 旅程 A：新租户开通（目标 ≤15 分钟到"首批线索在路上"）

```
注册 → ①AI 访谈建档（对话式 5 问：卖什么/优势/目标市场/客户类型/排除谁）
     → 自动生成：BrandKit 初稿 + 首个 Campaign 的 ICP 草案
     → ②接入发信邮箱（Google/Microsoft OAuth，或购买托管邮箱）
     → 系统检测 SPF/DKIM/DMARC → 未配置则给出 DNS 指引 → 自动开始预热
     → ③确认 ICP 并启动首个 Campaign
     → 结束页明确预期管理："预热期前 2 周日发 ≤20 封，第 3 周起爬坡到 50 封/账号"
```

设计要点：
- 三步进度条常驻，可跳过②先看线索（但发送被锁定，锁定原因明示）；
- AI 访谈可随时切换为表单模式（部分用户不习惯对话式）；
- **预期管理是留存关键**：冷启动期每天推送"预热进度 + 已找到的线索预览"维持信心。

### 5.2 旅程 B：业务员的每日循环（≤30 分钟，产品的心跳）

```
打开【今日待办】——三段式页面，从上到下按价值排序：
 1. 🔥 热线索（N 条）→ 逐条处理：看上下文 → 用/改 AI 草稿回复 → 标记交接
 2. ✍️ 待审批（N 封）→ 今日待发开发信抽检/逐封审批（按 Campaign 自动化级别）
 3. 📊 昨夜战报 → 新线索数、发送数、打开/回复数、域名健康，一屏读完
处理完三段 → 页面显示"今天的活干完了 ✅" → 用户离开
```

### 5.3 旅程 C：Campaign 生命周期

```
创建（四步向导）→ 预跑（AI 先出 20 条样本线索 + 3 封样信供确认）→ 启动
→ 运行中（线索持续流入 → 序列自动执行 → 回复进 Inbox）
→ 周报（AI 生成策略洞察：哪版主题行赢了、建议动作一键应用）
→ 暂停/归档
```

**预跑（Dry-run）是本产品独有的信任机制**：正式发送前用户先看到"AI 会找什么样的
公司、会写什么样的信"，校准后再放量——把 D2 原则做进流程里。

## 6. 关键状态机（产品行为的确定性来源）

### 6.1 线索状态（Lead Lifecycle）

```
发现 Discovered ──AI 研判──→ 已评分 Scored ──找到有效联系人──→ 就绪 Ready
    │（匹配度低/用户排除）           │（无有效邮箱）
    ↓                              ↓
  已排除 Excluded              待补全 Incomplete（定期重试挖掘）
就绪 Ready ──进入序列──→ 触达中 InSequence ──收到回复──→ 已回复 Replied
触达中 ──序列走完未回复──→ 已冷却 Cooled（90 天后可进再激活任务）
已回复 ──AI 分类──→ 热线索 Hot / 养熟中 Nurturing（定时回访）/ 已拒绝 Rejected
热线索 ──业务员处理──→ 已交接 HandedOff（导出/推 CRM/本系统继续跟）
任意状态 ──退订/投诉/硬退信──→ 已压制 Suppressed（终态，不可逆）
```

### 6.2 序列执行状态（每个 Contact × Campaign 一个实例）

不变量（NFR"可靠性"落地为产品规则，UI 需可见）：
1. 回复到达 → 该联系人**所有**在途步骤立即取消（含已排程未发出的）；
2. 同一联系人全局频控：跨 Campaign 每 30 天最多被 1 个序列触达；
3. 每步发送前重查压制名单与退信状态；
4. 发送窗口 = 收件人时区的工作日 08:30–11:30（默认，可调），窗口外只排队不发送。

### 6.3 发信身份健康状态

```
预热中 Warming（进度条+预计完成日）→ 健康 Healthy
Healthy ──退信率>3% 或 投诉率>0.1%──→ 降速 Throttled（自动减半量+告警）
Throttled ──持续恶化──→ 熔断 Paused（人工介入才能恢复）
```

健康状态在顶栏配额区常显（绿/黄/红点），点击进入诊断页——D4 原则的界面表达。

## 7. 页面级设计（MVP 全部 9 个页面）

### P1 今日待办（默认落地页）

- **布局**：三段纵向流（热线索 → 待审批 → 昨夜战报），每段可折叠，空段自动收起；
- 热线索卡片：公司名+国旗、联系人及职位、回复摘录（AI 高亮意向句）、
  AI 分类标签、〔查看会话〕〔用草稿回复〕两个主操作；
- 待审批区：卡片流逐封翻阅（信正文 + 右侧"AI 为什么这样写"依据面板），
  操作 = 通过 / 编辑后通过 / 拒绝并说明原因（原因回流训练偏好，FR-GEN-06）；
  顶部提供"抽检模式"开关（随机展开 N 封，其余批量通过）；
- 战报：四个数字块（新线索/已发送/打开/回复）+ 域名健康点 + 一句 AI 总结。

### P2 收件箱 Inbox

- 左列会话列表，按 AI 分类过滤（🔥感兴趣 / ❓有疑问 / ⏰以后再说 / ✋拒绝 / 🤖自动回复）；
- 右侧三栏会话视图：**往来邮件流（中）+ 公司档案与研判依据（右）**，
  回复框内置 AI 草稿（可重新生成、可改语气：更正式/更简短/加紧迫感）；
- "以后再说"类展示 AI 解析出的回访时间，一键确认创建回访（FR-RPL-04）；
- 交接按钮：导出 PDF/CSV、推送 Webhook、复制完整上下文摘要（给 CRM 粘贴）。

### P3 Campaign 列表 + 四步创建向导

列表页：卡片式，每卡显示微型漏斗（线索→触达→回复→热线索）、状态、A/B 胜者提示。
创建向导四步：
1. **定目标**：选目标市场（英语区国家多选）+ 行业 + 公司类型/规模 + 自然语言补充
   （"要找有实体门店的，不要纯电商"）→ 右侧实时预估线索池规模；
2. **选产品**：从 BrandKit 选本次主推产品与卖点（缺则引导补录）；
3. **定策略**：AI 生成序列草案（默认 4 步：D0 首信 → D3 跟进 → D8 换角度 → D15 收尾），
   每步可编辑；可开 A/B（2 版主题行）；设自动化级别（逐封/抽检/全自动）；
4. **预跑确认**：展示 20 条样本线索 + 3 封样信 → 用户校准（排除某类公司、改语气）
   → 启动。

### P4 线索库 Leads

- 公司视角表格：评分、国家、行业、来源、状态（§6.1）、归属人、最近动态；
- 行内展开研判档案：AI 匹配理由 + 事实清单（每条带出处链接，D3）；
- 批量操作：加入 Campaign、排除、导出；
- 撞单保护提示：他人名下线索置灰显示"已由 XX 跟进中"，不可加入自己的 Campaign。

### P5 会话详情（从 Inbox / 线索库进入）

即 P2 右侧三栏视图的全页版，增加：完整时间线（每次触达/打开/点击/状态变更）、
序列执行记录（哪步发了、哪步因回复取消）。

### P6 数据报表 Analytics

- 业务员视角：Campaign 漏斗对比、回复率趋势、最佳发送时段热力图；
- Admin 增加：团队看板（成员×漏斗矩阵）、每条热线索成本（FR-RPT-04，二期）；
- 送达健康页：送达/退信/垃圾箱率（种子探测）、各发信身份状态与预热进度。

### P7 设置-邮箱与域名

OAuth 接入向导、DNS 配置检测器（SPF/DKIM/DMARC 三项绿灯）、预热进度、
发送限额（默认锁定，Admin 可在护栏内调整——上限由系统按信誉动态给出，D4）。

### P8 设置-品牌资产库 BrandKit

结构化条目：公司简介、产品（图/参数/卖点/MOQ 区间）、认证证书、客户案例、FAQ。
每条标注"AI 可引用"开关。**明示规则：AI 写信只会使用此库与线索研判中的事实。**

### P9 设置-团队/合规/套餐

成员管理与线索转移；压制名单查看与手工添加；GDPR 删除请求处理入口；
套餐用量仪表（线索条数/发送量/AI 用量三个计量条）与升级入口。

## 8. 通知体系

| 事件 | 站内 | 邮件 | 移动推送(二期) | 时效要求 |
|------|------|------|----------------|----------|
| 🔥 新热线索 | ✓ | ✓ | ✓ | <5 分钟（NFR） |
| 待审批件到达每日批次 | ✓ | 摘要 | ✓ | 每日 1 次，用户自定时间 |
| 域名健康降级/熔断 | ✓ | ✓ | ✓ | 实时 |
| 周报（策略洞察） | ✓ | ✓ | — | 每周一 |
| 配额将用尽（80%） | ✓ | ✓ | — | 实时 |

原则：**除热线索与信誉告警外，一切通知合并为每日摘要**——不许打扰换来的注意力，
要花在真正值钱的事上。

## 9. SaaS 套餐与计量（产品侧初稿，定价待商业验证）

| | Starter（SOHO） | Growth（3–10 人团队） | Scale |
|---|---|---|---|
| 席位 | 1 | 5 起 | 10 起 |
| 新线索/月 | 300 | 1,500 | 定制 |
| 发送邮箱数 | 2 | 10 | 定制 |
| 自动化级别 | 全部 | 全部 | 全部 |
| 托管邮箱池 | 加购 | 加购 | 含 |
| 团队看板/撞单保护 | — | ✓ | ✓ |
| Webhook/CRM 推送 | — | ✓ | ✓ + API |

计量三轴：**线索条数（含研判）/ 邮件发送量 / AI 生成次数**，与 FR-SYS-06 对应；
超量软限制（降速+提示升级），不硬中断在途序列（保护用户的发信信誉与线索）。

## 10. 文案与视觉基调

- 界面语言：中文为主（用户是中国业务员），生成内容为英语；关键外贸术语保留英文；
- 视觉：清爽 SaaS 工作台风格，信息密度中等；状态色恒定语义
  （绿=健康/热，黄=注意/预热，红=风险/熔断，灰=已排除/压制）；
- AI 产出统一用"✨ + 依据可查看"的视觉记号，让用户始终分得清"AI 写的"与"事实"。
