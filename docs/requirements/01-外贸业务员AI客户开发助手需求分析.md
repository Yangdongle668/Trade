# 外贸业务员 AI 客户开发助手 —— 需求分析（V2.0）

> 视角：外贸行业专家 + 资深软件架构师
> 日期：2026-07-02
> 状态：初稿，待评审
> 说明：V2.0 重新定位产品方向 —— **不做 CRM/订单管理系统**，聚焦用 AI 替代业务员在
> "触达客户、开发客户、建立初步连接"环节中大量**重复且大多无效**的手工动作。

---

## 1. 产品定位

### 1.1 一句话定义

> 一个替外贸业务员干"开发客户"这件苦活的 AI 助手：**自动找到对的公司、挖到对的人、
> 用对方的语言写出千人千面的开发信、按最佳节奏多轮跟进，直到客户回复——
> 然后把"热线索"连同完整上下文交回给业务员本人去谈。**

### 1.2 边界（做什么 / 不做什么）

| 做（本产品核心） | 不做（明确排除） |
|------------------|------------------|
| 潜在客户发现（找公司） | 客户/订单/单证管理（CRM、ERP 范畴） |
| 决策人挖掘 + 联系方式获取与验证 | 报价、PI、生产跟进、收款 |
| AI 个性化开发信 / 多轮跟进序列 | 成交后的客户维护与售后 |
| 多渠道触达（邮件为主，LinkedIn/WhatsApp 渐进） | B2C 电商营销（如 Shopify 邮件营销） |
| 回复识别、意向分级、AI 草拟回复 | 广告投放（Google/Meta Ads） |
| 热线索交接（可推送/导出到客户已有 CRM） | 自建 CRM 与之竞争 |

**核心设计哲学**：AI 负责 100 次重复劳动，人负责 1 次关键对话。
客户一旦表现出真实意向，**必须无缝、快速地交回人类业务员**——外贸成交靠信任，
AI 的使命是把业务员的时间从 95% 的无效动作中解放出来，聚焦到 5% 的有效对话上。

## 2. 现状：业务员的客户开发日常（痛点根源）

### 2.1 典型的一天（无工具辅助时）

```
上午：Google 搜 "led lighting distributor Germany" → 逐个打开官网 → 翻 Contact/About 页
      → 猜邮箱（info@ / sales@）→ 复制粘贴到 Excel                      【2-3 小时】
下午：把上周的开发信模板改个称呼和公司名 → 一封封发出去（怕被判垃圾邮件不敢群发）
      → 顺手在 LinkedIn 上加几个人                                       【2-3 小时】
晚上：欧美客户上线，盯邮箱等回复；给一周前没回的客户发第二封跟进
      → 99% 石沉大海                                                    【1-2 小时】
```

### 2.2 量化的痛点

| # | 痛点 | 数据/事实 | 本质 |
|---|------|-----------|------|
| P1 | **找客户极其耗时** | 人工搜索+整理，一天产出 30–50 条线索，其中一半信息有误 | 信息检索是机器擅长、人不擅长的活 |
| P2 | **找不到关键人** | 拿到的多是 info@ 公共邮箱，进不了采购决策人的收件箱 | 缺乏决策人数据与挖掘手段 |
| P3 | **开发信千篇一律** | 模板信回复率 <1%；真正个性化的信回复率可达 5–10%，但一封要写 20 分钟 | 个性化与规模化在人力下互斥 → **AI 恰好同时解决** |
| P4 | **不敢发、发了进垃圾箱** | 公司主域名群发被拉黑，之后连正常业务邮件都进垃圾箱 | 缺乏发信基础设施知识（域名预热、SPF/DKIM/DMARC、节流） |
| P5 | **跟进靠毅力** | 统计上 80% 的回复来自第 2–5 次跟进，但多数业务员发 1–2 封就放弃 | 多轮跟进是纯机械动作，最适合自动化 |
| P6 | **时差错峰** | 客户当地时间上午 9–11 点打开率最高，业务员却在北京时间白天发信 | 定时发送即可解决，人做不到、机器轻松 |
| P7 | **语言天花板** | 英语尚可，但对小语种市场（西语、葡语、阿语、俄语）无能为力 | LLM 的多语言能力可直接变现 |
| P8 | **回复处理粗糙** | 收到回复后不会分类：自动回复/退订/婉拒/真询价混在一起，错过热线索 | 意图识别是 NLP 成熟场景 |
| P9 | **无数据复盘** | 不知道哪个行业、哪个国家、哪版话术回复率高，凭感觉调整 | 缺少漏斗数据 |

### 2.3 结论：自动化价值地图

```
                 人工耗时占比        AI 可替代度       本产品策略
找公司线索          ~30%              ★★★★★         全自动（人只定义 ICP）
挖决策人/邮箱       ~15%              ★★★★★         全自动
写个性化开发信      ~20%              ★★★★☆         AI 生成 + 抽检/审批
发送与多轮跟进      ~20%              ★★★★★         全自动（序列引擎）
回复识别与初步应答  ~10%              ★★★☆☆         AI 分类+草拟，人确认
深入谈判与成交       ~5%              ★☆☆☆☆         完全交还给人 ← 价值时刻
```

## 3. 用户画像与使用模式

### 3.1 主用户：外贸业务员

- 每天愿意花在本工具上的时间：**≤30 分钟**（早上看热线索 + 审批当日待发内容）；
- 期望的心智模型：**"数字员工/开发助理"**，而非"又一个要学的软件"；
- 信任是渐进的：初期想逐封审核 AI 写的信 → 熟悉后转为抽检 → 最终全托管。
  **产品必须支持这三档自动化级别（逐封审批 / 抽检 / 全自动）的平滑切换。**

### 3.2 次级用户

| 角色 | 诉求 |
|------|------|
| 老板/主管（中小外贸公司） | 花钱买线索产出：关心每条热线索成本、各业务员/各产品线的开发漏斗 |
| SOHO（一人外贸） | 预算敏感，希望一个人像一个团队；对全自动接受度最高 |

### 3.3 目标工作流（有本产品之后的一天）

```
09:00  打开工作台：AI 昨夜完成 —— 新挖掘线索 120 条（已按 ICP 匹配度评分），
       发出开发信 85 封（客户当地时间投递），收到回复 6 条。
09:05  处理热线索队列：2 条"索要报价/目录"（AI 已草拟回复并附上产品册，一键确认发送
       或改写后发送）；1 条"现在不需要，Q4 再联系"（AI 已自动安排 10 月回访）。
09:20  抽检今日待发的 20 封 AI 开发信（抽 3 封看），顺手把一句开场白改得更地道
       → 系统学习该偏好。
09:30  收工。剩下的时间去谈那 2 个要报价的客户。
```

## 5. 功能需求

编号规则 `FR-模块-序号`；优先级 MoSCoW。

### 5.1 ICP 定义与开发任务（Campaign）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-ICP-01 | 以自然语言 + 结构化条件定义理想客户画像（ICP）：目标国家、行业、公司类型（进口商/分销商/品牌商/连锁零售）、规模、我方产品与卖点 | M |
| FR-ICP-02 | **AI 访谈式建档**：新用户对话式回答"你卖什么、卖给谁、优势是什么"，AI 生成 ICP 与首版话术策略 | S |
| FR-ICP-03 | 开发任务（Campaign）管理：一个任务 = ICP + 渠道 + 话术策略 + 发送节奏；可暂停/复制/归档 | M |
| FR-ICP-04 | 每任务设置自动化级别：逐封审批 / 抽检（AI 自主，人可回看）/ 全自动 | M |
| FR-ICP-05 | 排除清单：已有客户、竞争对手、黑名单域名/国家（导入 CSV 或对接 CRM）不再触达 | M |

### 5.2 线索发现（找公司）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-LEAD-01 | **多源自动挖掘**：按 ICP 从数据源检索候选公司——搜索引擎、Google Maps、企业黄页/名录、B2B 平台公开信息、展会参展商名录、行业协会会员名单 | M |
| FR-LEAD-02 | 海关提单数据对接：查询目标市场进口商及其采购记录（采购品类、频次、现供应商），作为最高质量线索源 | S |
| FR-LEAD-03 | **AI 逐条研判打分**：AI 阅读候选公司官网/社媒，判断与 ICP 匹配度（0–100 分）并给出一句话理由（如"德国照明分销商，官网列有 LED 品类，规模约 50 人"） | M |
| FR-LEAD-04 | 去重与合并：跨数据源同一公司自动合并（按域名/名称模糊匹配）；与历史已触达线索去重 | M |
| FR-LEAD-05 | 线索池管理：按分数/国家/来源筛选，人工可标记"优质/排除"，反馈用于校准 AI 打分 | M |
| FR-LEAD-06 | 竞争对手客户挖掘：输入竞品名称，从海关数据/公开信息反查其买家 | C |
| FR-LEAD-07 | 相似客户扩展（Lookalike）：基于已成交客户特征，自动寻找相似公司 | C |

### 5.3 决策人挖掘与联系方式

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-CNT-01 | 从公司官网、LinkedIn 公开信息等识别关键角色：Owner / Purchasing / Sourcing / Product Manager，含姓名、职位、社交主页 | M |
| FR-CNT-02 | **邮箱发现与验证**：模式推测（first.last@domain）+ 第三方 Email Finder API + SMTP 存活验证，标注置信度；无效邮箱不进入发送队列 | M |
| FR-CNT-03 | 多联系人策略：同一公司找到多个角色时，按优先级依次或错峰触达，避免同时轰炸 | S |
| FR-CNT-04 | 电话/WhatsApp 号码采集（官网公开信息），供 WhatsApp 渠道使用 | S |
| FR-CNT-05 | 联系人合规属性：记录数据来源、采集时间，支持"被遗忘权"删除（GDPR） | M |

### 5.4 AI 内容生成（个性化开发信）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-GEN-01 | **千人千面开发信**：基于对方官网/新闻/领英动态生成个性化开场（如提及对方新店开业、新品线），正文结合我方卖点与对方业务的交集，≠ 模板套变量 | M |
| FR-GEN-02 | 多语言写作：至少支持英、西、葡、法、德、阿、俄；用客户母语写作并符合当地商务习惯 | M |
| FR-GEN-03 | 跟进信序列生成：第 2–N 封自动换角度（案例分享 → 行业洞察 → 优惠钩子 → 礼貌收尾），避免复读机式"Did you see my last email?" | M |
| FR-GEN-04 | **反垃圾写作规范内置**：控制字数、链接数、图片、敏感词（free/cheap/100%…），纯文本优先，自动检测 spam 分值 | M |
| FR-GEN-05 | 品牌资产库：公司介绍、产品卖点、认证证书、案例、FAQ 统一维护，作为 AI 写作的事实依据（防幻觉：**AI 不得编造价格、认证、交期**） | M |
| FR-GEN-06 | 人工反馈学习：业务员对 AI 草稿的每次修改被记录，沉淀为该用户的风格偏好 | S |
| FR-GEN-07 | A/B 测试：同一任务可并行 2–3 版策略（主题行/开场/CTA），按回复率自动倾斜流量 | S |
| FR-GEN-08 | 附件/落地页：支持插入产品册 PDF 链接或自动生成的单页介绍（带访问追踪） | C |

### 5.5 触达编排与发送基础设施（决定成败的隐形工程）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-SEND-01 | **序列引擎**：定义多步触达流（Day0 邮件 A → Day3 未回复则邮件 B → Day7 LinkedIn 访问 → Day14 邮件 C…），回复即自动停止序列 | M |
| FR-SEND-02 | **按收件人时区投递**：默认客户当地时间工作日上午发送，可配置 | M |
| FR-SEND-03 | **发信域名与信誉保护**：强制使用独立发信域名（非公司主域）；引导配置 SPF/DKIM/DMARC 并自动检测；新域名/新邮箱自动预热（warm-up）逐步提量 | M |
| FR-SEND-04 | 发送节流与多账号轮换：单邮箱日发限额（如 ≤50）、随机间隔、多邮箱负载均衡 | M |
| FR-SEND-05 | 退信/投诉处理：硬退信自动拉黑，退信率/投诉率超阈值自动暂停任务并告警 | M |
| FR-SEND-06 | 邮件追踪：送达、打开、点击（可关，因追踪像素影响送达率，默认保守策略） | S |
| FR-SEND-07 | LinkedIn 渠道：访问主页、好友申请、站内信的半自动执行（合规风险高，采用"生成内容+人一键执行"模式，不做黑产式自动化） | S |
| FR-SEND-08 | WhatsApp 渠道：基于 WhatsApp Business API 的合规触达（需模板消息审核），适用于已有初步互动的线索 | C |
| FR-SEND-09 | 全局频控：同一联系人跨任务全局触达上限；同一公司多联系人间隔保护 | M |

### 5.6 回复处理与热线索交接（价值兑现点）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-RPL-01 | **AI 回复分类**：感兴趣（索报价/目录/样品）/ 有疑问 / 现在不需要·以后再说 / 明确拒绝 / 退订要求 / 自动回复（OOO）/ 转介绍他人，分类准确率目标 ≥90% | M |
| FR-RPL-02 | **热线索队列**：感兴趣的回复置顶推送（站内+移动端通知+可选企业微信/邮件），附完整上下文（公司档案、往来记录、AI 研判摘要） | M |
| FR-RPL-03 | AI 草拟回复：针对常见回复（要目录、问 MOQ、问认证）基于品牌资产库草拟答复，**默认人审后发送**；简单场景可授权自动回复 | M |
| FR-RPL-04 | "以后再说"自动养熟：AI 识别时间意向（"contact me in Q4"）自动创建未来回访任务 | S |
| FR-RPL-05 | 退订/拒绝合规处理：自动移入全局压制名单（suppression list），永久不再触达 | M |
| FR-RPL-06 | **交接与导出**：热线索一键导出 CSV / 推送 Webhook / 对接主流 CRM（用户已有系统），附全部沟通历史 | M |
| FR-RPL-07 | 转人工后的会话接管：业务员可直接在本系统以绑定邮箱继续对话（保持线程），也可转回自己邮箱客户端 | S |

## 6. 关键用户故事

1. **定义即出活**：作为业务员，我用 10 分钟描述"我卖 LED 灯具，想开发德国和荷兰的照明分销商"，第二天就能看到 100+ 条打过分的线索和 AI 拟好的开发信，而不是自己搜一周。
2. **千人千面**：作为业务员，我希望发给每个客户的信都提到"他们家"的具体情况（官网上的品类、最近的新闻），因为我知道模板信没人回。
3. **放心睡觉**：作为业务员，我希望系统在客户当地时间上午自动发信、自动做第 2–5 轮跟进，我不用半夜守邮箱。
4. **别搞砸我的域名**：作为老板，我要求群发绝不使用公司主域名邮箱，且退信率异常时系统自动刹车，不能让公司邮箱进全球黑名单。
5. **热线索别错过**：作为业务员，客户回了"please send catalog and price list"时，我要在 5 分钟内收到手机通知，并且 AI 已经把回信草稿和产品册准备好。
6. **可控的信任**：作为业务员，第一周我要逐封审核 AI 的信；等我看顺眼了，切到全自动，只处理回复。
7. **拒绝合规风险**：作为老板，客户说 unsubscribe 后必须永不再收到我们的邮件，欧盟客户数据要可删除，否则罚不起。

## 7. 非功能需求（架构师视角）

| 类别 | 需求 |
|------|------|
| **送达率（第一 NFR）** | 送达率是产品生命线：预热、节流、信誉监控、内容 spam 检测形成闭环；目标垃圾箱率 <10%，退信率 <3% |
| AI 质量 | 生成内容零事实幻觉（价格/认证/参数只能来自品牌资产库，RAG + 校验）；回复分类准确率 ≥90%，热线索漏报率趋零（宁可误报） |
| 合规 | GDPR（数据来源合法、可删除）、CAN-SPAM/加州、加拿大 CASL：物理地址落款、一键退订、压制名单全局生效；LinkedIn/WhatsApp 遵守平台条款，不做账号农场 |
| 成本工程 | 单条线索的 LLM+数据 API 成本可核算、可控（分级模型策略：便宜模型做初筛，强模型写信）；批量任务用异步队列错峰 |
| 性能 | 挖掘与生成为离线批处理（夜间跑，早晨出结果）；回复分类与热线索通知须近实时（<5 分钟） |
| 可靠性 | 序列引擎必须精确幂等：绝不能给同一人重复发送、绝不能在对方回复后继续跟进（信誉事故） |
| 扩展性 | 数据源与触达渠道插件化：新增一个线索源/渠道不动核心流水线 |
| 多租户 | SaaS 形态，租户隔离；发信信誉按租户隔离（一个租户被投诉不连累其他租户） |
| 可观测 | 全链路追踪一条线索的生命周期；AI 决策日志可回放，支持问题归因 |

## 8. 迭代路线（建议）

### MVP（第 1 期，约 2–3 个月）—— 跑通"ICP → 线索 → 开发信 → 回复"最小闭环

- ICP 定义 + Campaign（FR-ICP-01/03/04/05）
- 线索发现（搜索引擎 + 官网研判打分 + 去重：FR-LEAD-01/03/04/05）
- 决策人与邮箱发现+验证（FR-CNT-01/02/05）
- AI 个性化开发信 + 跟进序列（英语优先：FR-GEN-01/03/04/05）
- 邮件序列引擎 + 时区投递 + 域名保护与节流（FR-SEND-01~05/09）
- 回复分类 + 热线索队列 + 退订压制 + CSV 导出（FR-RPL-01/02/05/06）
- 基础漏斗与送达健康度（FR-RPT-01/02）、邮箱 OAuth 接入（FR-SYS-02）

**MVP 成功指标**：单业务员周均产出 ≥5 条热线索；送达率 ≥90%；用户日均操作时间 ≤30 分钟。

### 第 2 期 —— 提质与多渠道

- 海关数据源、AI 访谈式建档、多语言写作全量、A/B 测试、AI 草拟回复、
  "以后再说"自动养熟、LinkedIn 半自动渠道、策略洞察周报、团队协作与撞单保护、移动端通知。

### 第 3 期 —— 智能深化与生态

- 竞对客户反查、Lookalike 扩展、WhatsApp Business API、会话接管、
  CRM 双向集成、托管发信邮箱池、风格学习个性化、成本 ROI 报表。

## 9. 关键风险与开放问题

| # | 风险/问题 | 影响 | 对策建议 |
|---|-----------|------|----------|
| 1 | **数据源合规与稳定性**：LinkedIn 反爬严格、海关数据按国别授权 | 核心供给受制于人 | 多源冗余 + 官方 API/正规数据商优先；LinkedIn 只做"人执行"半自动 |
| 2 | **送达率冷启动**：新域名新邮箱天然低信誉 | 首月体验差、用户流失 | 内置预热流程 + 明确用户预期（前 2 周小量）+ 可选托管成熟邮箱池 |
| 3 | AI 写信"恐怖谷"：个性化失败反而暴露是机器（张冠李戴） | 品牌受损 | 个性化事实必须有出处引用；低置信度时退化为通用但得体的版本 |
| 4 | 各国反垃圾法差异（GDPR vs 美国 CAN-SPAM 宽松） | 法律风险 | 按收件人所在国应用规则引擎；欧盟市场可加"合法利益"评估与 B2B 限定 |
| 5 | LLM 成本随规模线性上涨 | 毛利被吞噬 | 分级模型 + 缓存公司研判结果 + 批量推理；成本计入套餐配额 |
| 6 | 用户已有 CRM（小满/孚盟/HubSpot）| 数据孤岛担忧 | 定位为"前端获客引擎"，主动做好导出与 Webhook，不抢 CRM 地盘 |
| 7 | 目标形态：SaaS 多租户 or 私有化？ | 架构分叉点 | **建议 SaaS 优先**（发信基础设施与数据源集中运营才有规模优势），需求方确认 |
| 8 | 首发市场/语种范围？ | 影响 MVP 数据源选择 | 建议英语市场（欧美）先行，验证后扩小语种 |

## 10. 术语表

| 术语 | 说明 |
|------|------|
| ICP | Ideal Customer Profile，理想客户画像 |
| 开发信 | Cold Email，向陌生潜在客户发送的首封商务开发邮件 |
| 线索 (Lead) | 符合 ICP 的潜在客户公司/联系人 |
| 热线索 (Hot Lead) | 已回复且表现出真实采购意向的线索 |
| 序列 (Sequence) | 预设的多步骤、多轮次自动触达流程 |
| 预热 (Warm-up) | 新邮箱通过渐进式收发建立发信信誉的过程 |
| SPF/DKIM/DMARC | 三项邮件域名认证协议，影响是否进垃圾箱 |
| 压制名单 (Suppression List) | 永不触达名单（退订、投诉、硬退信） |
| 海关数据 | 各国进出口提单记录，可查真实进口商及其采购行为 |
| Warm-up / 养熟 | 对暂无需求的线索保持低频有价值触达，等待时机 |
