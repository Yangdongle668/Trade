# 外贸业务员需求分析（V1.0）

> 视角：外贸行业专家 + 资深软件架构师
> 日期：2026-07-02
> 状态：初稿，待评审

---

## 1. 背景与目标

### 1.1 背景

外贸业务员（Foreign Trade Sales / International Sales Rep）是外贸企业中最核心的角色之一，
其日常工作横跨 **客户开发 → 询盘处理 → 报价 → 打样 → 订单 → 生产跟进 → 出货 → 收款 → 售后/复购**
的完整链路。目前大量中小外贸企业的业务员仍依赖 Excel、微信/WhatsApp、邮箱、记事本等
分散工具管理业务，普遍存在以下问题：

- 客户信息散落在个人邮箱和聊天工具中，**离职即流失**；
- 询盘跟进靠记忆，**跟进不及时导致丢单**；
- 报价靠手工计算，**汇率、原材料波动导致报错价、亏本接单**；
- 订单进度靠追问工厂，**交期失控客户投诉**；
- 单证（PI/CI/PL 等）手工制作，**低效且易错**；
- 管理层看不到业务过程数据，**只能考核结果无法辅导过程**。

### 1.2 系统目标

为外贸业务员构建一套一体化工作台（外贸 CRM + 订单协同），目标是：

1. **客户资产企业化**：客户、询盘、往来记录沉淀到系统，不随人员流动流失；
2. **过程可管理**：跟进提醒、销售漏斗、任务待办，让"跟丢"变成小概率事件；
3. **报价快而准**：产品库 + 成本/汇率引擎，5 分钟出一份专业报价单；
4. **订单全程可视**：从 PI 到收汇核销，业务员和客户都能看到进度；
5. **数据驱动**：个人与团队的业绩、转化率、客户健康度一目了然。

### 1.3 本文档范围

本文档聚焦 **外贸业务员** 这一核心角色的需求分析。单证员、跟单员、财务、销售主管等
角色仅作为协作方出现，其完整需求将在后续文档中展开。

## 2. 用户画像与使用场景

### 2.1 核心画像：外贸业务员

| 维度 | 描述 |
|------|------|
| 典型年龄/背景 | 22–35 岁，国际贸易/英语等专业，英语读写流利 |
| 工作设备 | 公司电脑（Web 为主）+ 手机（客户随时找，需移动端） |
| 客户规模 | 人均维护 50–500 个客户/联系人，同时跟进 10–50 个询盘 |
| 沟通渠道 | 邮件（主）、WhatsApp/WeChat、阿里巴巴国际站 TM、LinkedIn、展会 |
| 时间特征 | 有时差，欧美客户集中在北京时间下午–凌晨活跃 |
| 考核方式 | 底薪 + 提成（按订单金额/毛利），强结果导向 |
| 数字化水平 | 熟练使用 Excel/邮箱，但排斥复杂、录入负担重的系统 |

**关键洞察（决定产品成败）**：

- 业务员天然抵触"给老板交数据"的系统，只有当系统**先帮他多拿单、少干杂活**，他才会真实使用；
- **录入成本必须极低**：能自动抓取（邮件同步、名片识别、询盘对接）就不要手工录入；
- **移动端是刚需**：客户消息随时来，报价、订单状态要能在手机上随手查。

### 2.2 协作角色（本期只做接口性设计）

| 角色 | 与业务员的协作点 |
|------|------------------|
| 销售主管/老板 | 分配公海客户、审批特价/账期、查看团队漏斗与业绩 |
| 单证员 | 接收订单信息，制作 CI/PL/产地证等出口单证 |
| 跟单员/采购 | 接收订单，跟进工厂生产、验货、交期 |
| 财务 | 收汇认领、核销、算提成 |
| 客户（外商） | 接收报价单/PI，确认订单，查看生产与物流进度（可选客户门户） |

### 2.3 核心业务流程（业务员一单的完整旅程）

```
获客/开发                询盘转化                     履约                    回款与复购
┌──────────┐   ┌──────────────────────┐   ┌─────────────────────┐   ┌──────────────┐
│ 展会名片   │   │ 询盘登记 → 背景调查    │   │ PI → 收定金 → 下单   │   │ 收尾款 → 核销 │
│ 平台询盘   │→ │ → 报价 → 议价 → 打样  │→ │ → 生产跟进 → 验货    │→ │ → 提成核算    │
│ 邮件开发   │   │ → 样品确认            │   │ → 订舱出运 → 单证    │   │ → 售后/返单   │
│ 社媒/官网  │   └──────────────────────┘   └─────────────────────┘   └──────────────┘
└──────────┘
```

各环节典型周期：询盘→成交 2 周–6 个月；订单履约 30–90 天；账期 0–90 天。
**系统必须适应长周期、多线程并行跟进的特点。**

## 3. 痛点分析（按业务环节）

| 环节 | 痛点 | 频次 | 影响 | 优先级 |
|------|------|------|------|--------|
| 客户开发 | 名片/询盘散落，重复开发同一客户，撞单内耗 | 高 | 中 | P1 |
| 询盘跟进 | 跟进无提醒，长周期客户被遗忘；不知道该跟谁、何时跟 | 高 | **高（直接丢单）** | **P0** |
| 客户背调 | 手工 Google 客户实力、海关数据，耗时且不专业 | 中 | 中 | P2 |
| 报价 | 手工算价易错；汇率/运费波动后旧报价单失效；版本混乱 | 高 | **高（亏本/报错价）** | **P0** |
| 打样 | 样品进度、快递单号、费用分摊无处记录 | 中 | 中 | P1 |
| 订单 | PI 手工制作；订单变更（数量/交期/规格）无留痕 | 高 | 高 | **P0** |
| 生产跟进 | 追问工厂靠嘴，交期延误发现太晚 | 高 | 高 | P1 |
| 单证物流 | 制单重复录入，箱单发票数据对不上；订舱信息传递靠微信 | 高 | 中 | P1 |
| 收款 | 尾款该收没人提醒；水单认领混乱；多币种对账困难 | 中 | **高（资金风险）** | P1 |
| 业绩提成 | 提成规则不透明，月底 Excel 对账扯皮 | 中 | 中 | P2 |
| 知识沉淀 | 邮件模板、话术、产品资料各存各的 | 中 | 低 | P2 |

## 4. 功能需求

需求编号规则：`FR-模块-序号`；优先级采用 MoSCoW（M=Must / S=Should / C=Could / W=Won't 本期不做）。

### 4.1 客户与联系人管理（CRM 核心）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-CUS-01 | 客户（公司）+ 联系人两级模型；一个客户可有多个联系人 | M |
| FR-CUS-02 | 客户字段：国家/地区、来源（展会/平台/官网/开发信…）、行业、规模、星级、标签、社交账号、时区 | M |
| FR-CUS-03 | **查重与撞单预警**：按公司名/域名/邮箱自动查重，录入时提示已有归属 | M |
| FR-CUS-04 | **公海/私海机制**：新客户可进公海；N 天未跟进/未成交自动掉回公海，可配置规则 | M |
| FR-CUS-05 | 客户 360° 视图：一页看到所有联系人、跟进记录、询盘、报价、订单、邮件、附件 | M |
| FR-CUS-06 | 名片扫描识别录入（OCR），移动端支持 | S |
| FR-CUS-07 | 客户背景调查：对接海关数据/企业信息 API，展示采购记录与供应商 | C |
| FR-CUS-08 | 客户分级与健康度：按互动频率、订单金额自动打分，提示流失风险 | S |
| FR-CUS-09 | 客户转移/离职交接：批量转移客户及全部历史记录给其他业务员 | M |

### 4.2 询盘与跟进管理（销售过程）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-INQ-01 | 询盘登记：来源、产品、数量、目标价、贸易条款；可从邮件一键转询盘 | M |
| FR-INQ-02 | **销售漏斗/商机阶段**：询盘→报价→样品→谈判→赢单/输单，看板拖拽 + 列表两种视图 | M |
| FR-INQ-03 | **跟进记录 + 下次跟进提醒**：记录每次沟通，强制/建议设置下次跟进时间，到期提醒 | M |
| FR-INQ-04 | 今日工作台：今天该跟进的客户、逾期未跟进、待办任务聚合成一页 | M |
| FR-INQ-05 | 输单原因分析：关闭询盘时选择原因（价格/交期/无回复…），供复盘统计 | S |
| FR-INQ-06 | 邮件集成：绑定业务邮箱（IMAP/SMTP 或 Gmail/Outlook API），往来邮件自动归档到客户/询盘下 | S |
| FR-INQ-07 | 邮件模板库 + 变量替换（客户名、产品、报价单链接），支持团队共享模板 | S |

## 5. 关键用户故事（示例）

1. **跟进提醒**：作为业务员，我希望每天打开系统就看到"今天必须跟进的 8 个客户"，并能一键发邮件/记录结果，以免长周期客户被遗忘。
2. **快速报价**：作为业务员，我希望选好产品和数量后系统按当日汇率自动算出 CIF 价并生成 PDF 报价单，10 分钟内回复客户，以提升询盘响应速度。
3. **撞单保护**：作为业务员，我录入新客户时希望系统告诉我这个域名是否已被同事跟进，避免内部撞单和恶性比价。
4. **订单透明**：作为业务员，我希望不用追问跟单员就能看到订单当前处于"生产中，预计 7/15 完成"，并在延期时收到预警，以便提前安抚客户。
5. **尾款提醒**：作为业务员，我希望货物到港前 7 天系统提醒我催收 70% 尾款，避免货到目的港客户拖款的被动局面。
6. **离职交接**：作为主管，业务员离职时我希望一键把其名下客户及全部沟通历史转给接手人，保证客户无感知过渡。

## 6. 非功能需求（架构师视角）

| 类别 | 需求 |
|------|------|
| 性能 | 常规页面 P95 < 1s；客户/邮件全文检索 < 2s；单公司支持 10 万级客户、百万级邮件归档 |
| 可用性 | 目标 99.9%；业务员分布全球时区，无可接受的固定停机窗口，需支持灰度/滚动发布 |
| 安全 | 客户数据是企业核心资产：字段级权限、导出审计与限流、防爬；传输 TLS、敏感字段加密存储 |
| 合规 | 涉及境外个人数据（GDPR 意识）；邮件同步需用户明确授权（OAuth 优先，避免存明文密码） |
| 多租户 | SaaS 形态按租户隔离（共享库 + tenant_id 起步，预留独立库能力）；若私有化部署则简化 |
| 集成性 | 预留开放 API/Webhook：邮箱、汇率、海关数据、物流轨迹、阿里国际站询盘、WhatsApp Business |
| 可扩展 | 模块化：CRM、报价、订单、单证、财务松耦合，支持按模块渐进交付 |
| 易用性 | 关键操作 ≤3 次点击；表单支持草稿；批量操作；全局搜索（客户/邮箱/订单号/柜号） |
| 国际化 | UI 中英双语；数据层面多币种（金额+币种+汇率快照三元组）、日期时区正确处理 |

## 7. 范围界定与迭代路线（建议）

### MVP（第 1 期，建议 2–3 个月）—— 先让业务员"离不开"

- 客户/联系人管理 + 查重 + 公海（FR-CUS-01~05, 09）
- 询盘/商机漏斗 + 跟进提醒 + 今日工作台（FR-INQ-01~04）
- 产品库 + 报价计算 + PDF 报价单（FR-QUO-01~04）
- 订单/PI + 状态流 + 收款计划与登记（FR-ORD-01~03, FR-PAY-01~02）
- 权限、审计、导入导出、个人仪表盘（FR-SYS-01~03, 07, FR-RPT-01）

### 第 2 期 —— 打通协作与自动化

- 邮件集成与自动归档、邮件模板
- 样品管理、生产协同、出运信息、CI/PL 单证生成
- 应收看板、汇率自动更新与报价管控、团队报表、移动端

### 第 3 期 —— 智能化与生态

- 海关数据背调、客户健康度模型、AI 写信/翻译
- 客户门户、在线报价链接、WhatsApp 对接、提成引擎、更多单证

### 本期明确不做（Won't）

- 报关系统直连、退税管理、工厂 MES/ERP 深度集成、跨境电商（B2C）场景。

## 8. 风险与开放问题

| # | 问题 | 影响 | 建议 |
|---|------|------|------|
| 1 | 目标形态是 SaaS 多租户还是单一企业自用？ | 决定租户模型、计费、部署架构 | 需求方确认；架构上先按"共享库多租户"设计，自用视为单租户特例 |
| 2 | 是否必须对接阿里国际站/环球资源等平台询盘？ | 平台 API 授权门槛高 | MVP 用"邮件转询盘 + 手工录入"，二期再接平台 |
| 3 | 邮件同步的合规与技术方案（IMAP vs OAuth） | 涉及账号安全与国际邮箱可达性 | 优先 Gmail/Outlook OAuth，IMAP 作兜底 |
| 4 | 成本价数据是否愿意录入系统？ | 报价计算器价值依赖成本数据 | 支持"仅售价模式"降级使用，成本可选填 |
| 5 | 业务员抵触录入 | 系统沦为摆设 | 设计原则：自动采集 > 一键转化 > 手工录入；移动端降低门槛 |
| 6 | 提成规则各公司差异极大 | 规则引擎复杂 | 后置到第 3 期，先提供数据导出供财务算提成 |

## 9. 术语表

| 术语 | 说明 |
|------|------|
| 询盘 (Inquiry) | 客户发来的购买意向咨询 |
| PI (Proforma Invoice) | 形式发票，外贸中通常起订单合同作用 |
| CI / PL | Commercial Invoice 商业发票 / Packing List 装箱单 |

| MOQ | Minimum Order Quantity，最小起订量 |
| HS Code | 海关商品编码，用于报关与关税 |
| ETD/ETA | 预计开船日 / 预计到港日 |
| 水单 | 银行汇款凭证（Bank Slip / MT103） |
| 核销 | 将收到的外汇款项与对应订单应收进行匹配确认 |
